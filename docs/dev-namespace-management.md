# Dev namespaces and Istio demo profile

The dev ApplicationSet derives destination.namespace from apps/<app>/overlays/dev
and sets managedNamespaceMetadata.labels.istio-injection=enabled. CreateNamespace=true
creates each destination namespace before syncing application resources. Namespace
prune protection is retained through managedNamespaceMetadata.annotations with
argocd.argoproj.io/sync-options=Prune=false.

Bookinfo no longer renders a Namespace manifest; its previous namespace resource
had Prune=false before removal, so migration does not delete the namespace or its
workloads. Existing pods do not automatically restart when namespace labels change.
Do not combine a Namespace manifest for the same destination with managed metadata:
the explicit manifest takes precedence. All apps generated by dev inherit the same
injection policy; apps that need different policies require separate configuration.

All five installed Istio charts (base, istiod, CNI, ingress gateway and egress gateway)
select profile: demo in Helm values. Istio remains in sidecar mode with CNI integration.
User values override the preset: Alloy/Envoy telemetry, 100% tracing and direct HTTP
LoadBalancer access on port 8080 remain configured. The chart profile is a set of
Helm defaults; it does not install additional charts such as ztunnel or observability
backends automatically. Demo resource defaults apply to newly created proxy pods;
existing application proxies require a rollout to receive new injected defaults.
